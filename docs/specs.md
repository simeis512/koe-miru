# 両声類向け音声トレーニングHUD Webアプリ 仕様書

## 1. プロジェクト概要
VR空間でのオーバーレイ表示や、配信画面のHUD（ヘッドアップディスプレイ）としての利用を想定した、完全ローカル動作のリアルタイム音声解析・視覚化Webアプリケーション。
「kawaiivoiceを目指す本」等の知見に基づき、声の高さ（ピッチ）だけでなく、声質（フォルマント）や発声状態（倍音）を総合的に判定し、目標とする音声（ターゲット）への接近度を直感的な図形と色でフィードバックする。

## 2. 技術スタック
* **フレームワーク:** Next.js (App Router)
* **スタイリング:** Tailwind CSS
* **UIコンポーネント:** shadcn/ui (Tooltip, Button, HoverCard/Popover等), lucide-react (アイコン)
* **音声信号処理:** Web Audio API, AudioWorklet
* **解析ライブラリ:** fairly-fast-formants (WasmによるLPC解析), Pitchfinder (F0検出)
* **リアルタイム描画:** HTML5 Canvas API (ネイティブ実装)
* **デプロイ先:** Vercel (GitHubリポジトリ連携)

## 3. 画面レイアウト・UI設計
画面全体をスクロール不可の1画面（SPA）とし、ダークモードを基調とする。
クラス設定例: `h-screen w-screen overflow-hidden bg-black text-white`

### 3.1. 画面構成（3ペイン）
* **左側 (幅15%): 発声状態・カラー設定エリア**
  * 発声の安定度（倍音の豊かさ＝裏声の回避）を示すインジケーターを配置。
  * 画面左端に「自分の声(Current)」「ターゲット(Target)」「一致時(Match)」の3つの色を示す小さな円を縦に配置。
  * 各円にホバーすると `HoverCard` が開き、ラベル名と5色程度のカラーパレットが表示され、クリックでアプリ全体のテーマカラーが即座に変更される。
* **中央 (幅70%): メインマップ (Canvas 2D) ＆ D&Dエリア**
  * F3(X軸) / F4(Y軸) をベースとした2次元マップをCanvasで全面描画。
  * 画面全体がターゲット音声ファイル（.wav / .mp3）のDrag & Drop領域として機能。
* **右側 (幅15%): ピッチ(F0)インジケーター**
  * 縦型の温度計・スライダー風UI。
  * 目標となる女性声の帯域（例: 210Hz〜270Hz）の背景をハイライト表示。
  * 現在のピッチに応じてバーが上下し、帯域内なら緑、低ければ青、高すぎれば赤のようにシームレスに色が変化。

### 3.2. ターゲット音声の読み込みUI
* **ステルスボタン:** 画面右下に目立たない透明ボタン（`variant="ghost"`）を配置。
* **未読み込み時:** 🎵アイコンを表示。Tooltipで「ターゲット音声を読み込む」と案内。クリックでファイル選択ダイアログ展開（D&Dの代替手段）。
* **読み込み後:** 内部で音声を一括解析し、平均F3/F4、ピッチ等をターゲット値として保持。ボタンは「✕」アイコンに変化し、クリックでターゲットをリセット（解除）する。

### 3.3. 視覚的フィードバック（Canvas描画）
文字情報を極力減らし、直感的な図形アニメーションで表現する。
* **ターゲット:** マップ上の固定された大きな円（ゆっくり明滅）。
* **自分の声:** マップ上をリアルタイムに動き回る光る球体。
* **テザー（紐）表現:** 自分の声とターゲットを線で結び、距離（ユークリッド距離）が近づくにつれて線を「太く・暖色（設定されたMatchカラー）」に変化させる。
* **到達エフェクト:** 自分の声がターゲットの円内（許容誤差範囲）に入ると、ターゲットの円全体が発光し、パーティクルが弾けるエフェクトを描画。

## 4. 音声解析ロジック（評価指標）
以下の指標をリアルタイムに抽出し、UIに反映させる。
1. **第3・第4フォルマント (F3, F4):** LPC（線形予測符号化）を用いて抽出。性別・年齢感の主軸（女性・ロリ声は高周波へシフト）。中央のマップ座標に適用。
2. **基本周波数 (F0 / Pitch):** 声の高さ。右側の縦型ゲージに適用。100Hzを下回る場合は警告表示。
3. **倍音の数 (Overtones):** 2000Hz以下のピーク数をカウント。少ない場合（裏声・過緊張）は左側のインジケーターで警告。
4. **抑揚 (Pitch Variance):** 過去数秒間のF0の変動幅。のっぺりした男性的な喋りを検知する補助スコア。

## 5. 開発時の重要注意事項・技術的制約（AIへの指示事項）
本プロジェクトをVibeコーディング（AI生成）で進めるにあたり、以下の制約を厳守すること。

1. **AudioContextの初期化タイミング:**
   ブラウザの自動再生ポリシーを遵守するため、マイクへのアクセスおよび `AudioContext` の生成は、必ずユーザーの初回インタラクション（画面クリックや「開始」ボタンの押下）の後に実行されるように実装すること。
2. **WebAssembly (Wasm) と AudioWorklet の配置:**
   Next.jsのApp Router環境におけるWebpackのバンドルエラーを回避するため、`fairly-fast-formants` 等のWasmファイルや、AudioWorkletのプロセッサーファイル（例: `processor.js`）は、npmモジュールから直接importするのではなく、**必ず `public` ディレクトリ配下に静的ファイルとして配置し、フロントエンドからURL経由で読み込む設計にすること**。
3. **Canvas描画のパフォーマンス最適化:**
   60fpsでのリアルタイム描画を行うため、Canvasの更新にReactのState（`useState`）を使用しないこと（再レンダリングによるパフォーマンス低下を防ぐため）。必ず `useRef` でCanvas要素と最新の解析データを保持し、`requestAnimationFrame` を用いたVanilla JSのループ内で描画処理を完結させること。
4. **プライバシーとローカル処理:**
   音声データの外部サーバーへの送信は一切行わない。すべての音声解析およびターゲット音声の処理はクライアントサイドのブラウザメモリ内で完結させること。
